### 端到端坐实（不是单元假象）
分页器用例走 `Answerer._tryNonStandardAB` 真实入口：
```
readOptions().texts        = ["1","2","3"]
Solver.solve 收到的 options = ["1","2","3"]
被 Filler.clickOption 点击   = ["1@DIV.number"]   ← 真的点了页码！
★ P1 确认：脚本点了分页器页码
```
分页器正是 team-lead 指出「智慧树弹题里真实存在」的结构 → 生产可触发概率高。

### 根因（`:555`）
```js
if (deduped.length > best.length || (deduped.length === best.length && depth > bestDepth)) {
```
判据是**「更长优先，等长取更深」** → 任何 3~4 项对称兄弟组天生压过 2 项真选项。实测机理：`.opts`(2 项) 与 `.el-pager`(3 项) 同深度，分页器以「3>2」直接胜出；面包屑 3 项同理。**方案C 无任何"这组是不是选项"的正向判据**（不看与题干的邻近性、不看 class 语义、不看是否在选项容器内），仅靠"兄弟整齐"就入选，因此噪声面比方案B 大得多。

**建议**：方案C 仅在**方案A/B 全空**时兜底（现已是），但需再加正向约束，如「组内文本**不含纯数字/纯符号**」「组不得是 Element UI 分页/步骤/选项卡 class（`el-pager/el-step/el-tabs__item/el-breadcrumb`）」「组元素须为 block 且文本长度 > 1」；并把「更长优先」改为「更接近题干优先」或「长度==2 优先」。

## 2. **P1（阻塞发布）—— 方案C 与方案B 叠加：等长时噪声被保留**

`:416 if (picked.length > els.length) els = picked;` 是**严格大于**才替换。实测：方案B 从噪声组拿到 2 项、方案C 拿到 2 项真选项时，**长度相等 → 保留方案B 的噪声**（实测 `readOptions.texts=["真选项一","真选项二"]` 未含噪声，但与「方案B 先命中、长度相同」的路径耦合脆弱）。当前用例侥幸正确，但判据本身不区分来源可靠性 → 应改为「方案C 命中且来源更可信时无条件采用」或比较元素是否落在题干同容器。

## 3. **P2（不阻塞）—— 深度上限 6 层静默失效**
8 层嵌套选项组：`readOptions.texts = []`、`_autoSiblings = 0`（6 层仍得 2 项）。真实弹窗若 >6 层选项容器 → 方案C 静默失效且**无日志**。建议超限时打 debug 日志。

## 4. **P2（不阻塞）—— NAV_WORDS 误杀真题选项**
7 个导航词**逐一**作为选项文本（配另一真选项）实测，**每个都导致整组 `readOptions=[]` → 完全答不了**：
```
选项含「上一题/下一题/继续学习/返回/我知道了/知道了/提交答案」+「另一个选项」→ readOptions = []  ❌
```
机理：2 项组被摘掉 1 个 → `kept.length<2` → `continue`（`:457`/`:546`）。
- 「继续学习」「返回」是**很可能的真题选项文本**（如「学习完成后应如何操作？→ 返回/继续学习」），风险高于「上一题」。
- 内部不一致：`继续学习`同时在 `ACTION_WORDS` 与 `NAV_WORDS`，被 NAV 抢先生效而误杀；而 `确定`（同为操作词）却因不在 NAV 幸存。同类文本得到相反待遇。
- 建议：NAV 摘除后若剩 <2，**回退为不摘**（宁可用原组交 Solver），或仅当组内**多数**为导航词时才弃组。

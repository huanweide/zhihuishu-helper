## 1. **P1（阻塞发布）—— `NOISE_CLASSES` 祖先链匹配把整题真选项全灭**

`inNoiseContainer` 沿**祖先链**走 ≤40 层做分词匹配，只要弹窗**任一层祖先**命中黑名单，**组内真选项全被判噪声**。实测：

| 用例 | readOptions().texts | 判定 |
|---|---|---|
| 弹窗外层含 `courseware-menu` | `[]` | ❌ 全灭 |
| **弹窗嵌在 `video-js` 容器内**（智慧树很可能如此！） | `[]` | ❌ 全灭 |
| 选项自身 class = `el-menu-item` | `[]` | ❌ 全灭 |

**这正是 team-lead 点名"风险最高"的场景，已坐实。** 弹题 DOM 若挂在播放器容器（`video-js`/`dplayer`/`artplayer`/`prism-player`，全在黑名单里）之下，脚本将对**所有**弹题读不到选项 → 退化为"猜两次"或直接放弃。

**对照（分词匹配本身工作正常，未误伤）**：`el-menu-panel`、`el-menu-item-sub` 不会被 `el-menu` 命中（1a/1d 仍读到 2 真选项）✓ —— 说明是**祖先链范围**过宽，而非分词有误。

**建议**：黑名单只对**元素自身 + 最近 2~3 层**生效，或改为「命中噪声容器**且**该容器不含题干特征」才弃组；至少把 `video-js/dplayer/artplayer/prism-player/vjs-control-bar` 从"祖先即判罪"降级为"仅元素自身命中才判罪"。

## 2. **P1（阻塞发布）—— 打分制可被前缀操纵：3 项带前缀噪声压过 2 项真选项**

打分公式 `scoreOptionGroup`：2 项 +100、3 项 +30、A./B. 前缀 **每个 +40**。实测：
```
噪声[3项, 带A./B./C. 前缀] = 30 + 3×40 + len/50 + depth = 111.3
真组  [2项, 无前缀]        = 100 + 0 + len/50 + depth   = 101.3
→ 噪声 111.3 > 真组 101.3 ⇒ 噪声胜出
readOptions().texts = ["A. 首页","B. 课程","C. 章节"]   ← 面包屑盖掉真选项
端到端：Solver 收到 ["A. 首页",...]；Filler 实点 "A. 首页@DIV.it"   ← 真的点了面包屑！
```
「前缀奖励 ×40」权重过高，**任何 3 项带 A./B./C. 的列表**（面包屑/选项卡/步骤条若带序号）都能翻盘。4 项带前缀反而不胜（+10 基数太低），说明权重设计不单调，可被针对性构造。
**建议**：前缀奖励应**从属于项数判据**（如 `2 项 = 强正向，其余前缀加分仅在 2 项时计`），或将 2 项权重提到 >「4 项 + 4 前缀」上限。

## 3. **P1（阻塞发布）—— NAV 回退把页脚导航当选项送去解题并真点**

`fellBack → kept = g.slice()` 后**跳过「全操作词弃用」**，页脚 2 按钮组直接成为选项。实测端到端：
```
页脚 [上一题][下一题] → readOptions=["上一题","下一题"] → Solver 收到同 → Filler 实点 "上一题@BUTTON.fbtn"
页脚 [返回][继续学习] → readOptions=["返回","继续学习"] → Filler 实点 "返回@BUTTON.fbtn"
```
旧版（0.6.23）此场景返回 `[]`（读不到，不误点）。**trade-off 明确：从"读空不动作"变成"点错导航按钮"（真实平台会切页/交卷），后者更糟** → 新 P1。回退本意是救「返回」当选项的真题，但代价是页脚组失控。
**建议**：回退时仍保留「全部成员 ∈ ACTION_WORDS**且**全是 button/导航标签」的否决；或仅在「组内无 button 标签、且有题干兄弟」时回退。

## 4. **P1（阻塞发布）—— `isSingleNoiseToken` 误杀 `√`/`×` 判断题选项**
```
OPTION_TEXT_RE.test("√")=true, test("×")=true   ← 正则明确认它们是选项
isSingleNoiseToken("√")=true → 被当"单符号"弃用
实测 √/× 判断题：readOptions=[]  ⇒ 完全答不了
```
`√`/`×` 是**判断题的标准选项文本**，正则专门有 `√|×` 分支认它们，形状判据却弃用 → **两条判据自相矛盾**。另「1」「2」当选项也被误杀（`❌`），而「是/否/对/错/A/B/甲」保留 ✓。
**建议**：`isSingleNoiseToken` 对 `√ ×` 白名单放行（与 OPTION_TEXT_RE 对齐）；单数字仅在「同组全数字」时才弃（现 `looksLikeNoiseTexts` 已做，成员级再挡属重复且过严）。

> 侦察方式：playwright-cli 0.1.22 操控**已登录态的 Edge 真机**（本地持久 profile，session 名 `zhs`），逐条对照真实 DOM 验证

> 证据快照：`zhs-popquiz.yaml`（弹题出现时）、`zhs-afterclose.yaml`（关弹题后）、`zhs-video.yaml`（视频页）、`zhs-doexam.yaml`（考试页）

## 〇、先说结论（一句话定位）

插件当前的目标是"看课刷进度 + 答题"，而课中弹题是 **AI 助教小智现场生成的"巩固题"**（文案明确写"不影响作业和考试成绩"）。

【round-29 复测修正，2026-10-19】下面有两条结论**被第二轮真机测试推翻**，以本版为准：

1. **"答案恒定内嵌 DOM"是错的** —— 同一门课 4.4 小节弹出的单选题（选项 `A.1 / B.3`、题干是图片）
   **从头到尾没有 `正确答案`**，**点选选项之后也不会出现**。1.1 那次看到的内嵌答案只是**部分题**的行为。
   正确口径：**有就抄近路读 DOM，读不到必须老实降级**，绝不能假设一定有。
2. **真正的挂机杀手是"关弹题会整页跳门户"** —— 点弹题的「关闭」按钮后，页面**稳定**跳到
   `www.zhihuishu.com`（连测 2 次都跳），比验证码更容易中断挂机（详见 P0-0）。

所以挂机自动化的核心闭环是：**识别弹题 → 有答案就读、没答案就按常规答题 → 关闭 → 续播 → 若被跳走则自动回学习页**。
另一条硬骨头仍是**腾讯 Turing 滑块拼图验证码**（由异常 seek 触发，已通过"零 seek"从源头规避）。

## 二、问题清单（按阻断严重性排序）

### 【P0-0】关掉弹题会**稳定**整页跳门户首页（round-29 新增 · 挂机第一杀手）

- **现象**：点弹题的「关闭」按钮（`div.btn`，文本「关闭」）后弹窗确实消失，但**页面立刻整页导航到 `https://www.zhihuishu.com/`**。
- **复现强度**：同一门课（线性代数 4.4）**连测 2 次，2 次都跳** —— 不是偶发风控，是**确定性行为**，比验证码更容易中断挂机。
- **危害**：跳走后既没有 `video`、也读不到课程目录。`findNext` 因目录为空返回 null → 被判成「没有下一节 / 全部看完」而**误停**，挂机当场断掉。
- **修复（已落地 v0.6.34）**：`05-scheduler.js` 新增**守卫 0** —— 在学习页时记住 `location.href`；一旦连续 3 轮（约 6 秒）读不到课程目录，就自动跳回记住的学习页。留 3 轮是为了避开「页面刚加载、目录还没渲染」的误判。
- **补充**：右上角 X（`.el-dialog__close` / `.el-dialog__headerbtn`）用合成事件**点不掉**这个弹窗；实测只有「关闭」文字按钮能关。

### 【P0-1】弹题容器确认就是 `#playTopic-dialog`（round-29 更正上一轮误判）

- **更正**：上一轮我据无障碍树的 `dialog "弹题测验"` 断言「旧文档的 `#playTopic-dialog` 已作废」——**这是误判**。a11y 名与 DOM 选择器指的是**同一个元素**：
  `div#playTopic-dialog.el-dialog__wrapper.dialog-test`。
  因此插件 `QUESTION_SELECTORS` 里原有的 `#playTopic-dialog` **是准的**，本节原「选择器永远为空」的结论作废。
- **真机 DOM 关键节点**（1.1 那次，来自 `zhs-popquiz.yaml`）：
  ```
  #playTopic-dialog（a11y 名「弹题测验」）:
    「AI助教小智给你出题啦！学习过程中有问题，随时点我」   ← 弹题特征标志
    「弹题是为了帮助同学们巩固知识点，不会影响到大家作业和考试的成绩。」
    「正确【单选题】」 + img 图片2.png    ← 题型标注嵌在段落，题目可能带图
    li.topic-item: A.(-4,0,-5,-9) / B.(4,5,0,9) / C.(0,4,5,9) / D.(4,0,5,0)
    div.btn: 关闭                        ← 真正能关掉它的按钮
  ```
- **另一处修正**：弹题**不一定**在 88% 出现。1.1 是 482/546≈88%，而 4.4 在 ct=284/515≈**55%** 就弹了。
- **还有**：弹题弹出时**不保证暂停视频** —— 4.4 第二次弹出时 `paused=false`，视频仍在播。

### 【P0-2】答案内嵌只是「部分题」的行为，不是恒定规律（round-29 修正）

- **1.1 那次**：弹题里有 `正确答案：A`（据此上一轮写成了"答案直接写在 DOM"）。
- **4.4 那次（推翻）**：选项 `A.1 / B.3`、题干是图片，**全文没有「正确答案」**；而且**点选 A 之后依然不出现**。
- **正确口径**：
  - 读得到 → 走快路径（跳过 `09-bank` → `11-solver` → `13-answerer` 整条重链路，省 token、零误判）；
  - **读不到 → 必须老实降级**回原答题链路，绝不能假设一定有答案，更不能因为读不到就卡死在"必须答上才关"。

### 【P1-1】点选项不改选中态，"选答案"步骤在弹题上失效

- **实测**：在 `zhs-popquiz.yaml` 状态下点击 `listitem A`（e668），再 snapshot，**listitem 的 class / 结构没有任何变化**（没有 `is-checked`、没有选中标记）。
- **含义**：对这类 AI 巩固弹题，"先把选项点选上再关闭"是**不必要甚至无效**的动作——既然答案已经写在 DOM 里且不影响成绩，挂机场景下**直接关弹题即可**，不需要模拟"选对答案"。
- **修复方向**：弹题快路径里**不要尝试模拟点选**，直接读答案 + 关弹题 + 续播。把"点选项"逻辑只留给真正要计分的作业/考试场景（见 P2-2）。

### 【P1-2】关弹题后视频不自动续播，必须手动 `video.play()`

- **实测**（`zhs-afterclose.yaml`）：点「关闭」后 `dialog` 消失，但 `region "video player"` 恢复后视频仍是 `paused` 状态，进度停在弹题暂停点（约 88%）。单独调 `video.play()` 后续播成功（ct 482→498，paused:false）。
- **阻断点**：插件若只做"关弹题"，视频会永远停在暂停点，进度卡死，等于没挂机。
- **修复方向**：关弹题后**强制补一步 `video.play()`**，并轮询确认 `paused === false`；若被验证码挡住（见 P0-3）则先处理验证码再 play。

### 【P0-3】腾讯 Turing 滑块拼图验证码（iframe 常驻 + 触发即阻断）

- **现象**：视频页 DOM 里**常驻一个验证码 iframe**（`zhs-popquiz.yaml` / `zhs-afterclose.yaml` 末尾均有）：
  ```
  iframe:
    安全验证
    拖动下方滑块完成拼图
    img "feedback" / img "refresh"
  ```
  来源域名 `turing.captcha.gtimg.com`（腾讯系）。它是**反爬风险控制元素**，平时可能隐藏，一旦检测到"非人类节奏"（如倍速狂刷、弹题瞬间秒关、长时间无操作）就会**变成阻塞式弹层**挡住播放。
- **阻断点**：
  - 跨域 iframe：用 `eval` 直接访问其内容会抛 `SecurityError`，必须切到该 iframe 上下文或靠视觉/截图判断。
  - 滑块拼图是**行为验证**，纯脚本无法稳定过（需要真实拖拽轨迹 + 缺口识别），属于人工兜底项。
- **修复方向**：
  - **节奏防御优先**：弹题关闭不要"秒关"，加 0.5~1.5s 随机延迟；倍速不要长期拉满；保留合理播放间隔，降低被风控触发概率。
  - **检测 + 暂停 + 人工提示**：轮询检测到验证码 iframe 变为可见/阻塞时，**暂停自动流程**，在界面高亮提示用户手动过码，过完再 `video.play()` 继续。
  - 不尝试自动破解滑块（成功率低、且违反平台规则风险高）。

### 【P2-1】弹题题型可能带图片，题干解析要兼容图文混排

- **现象**：本次弹题题干后跟 `img "图片2.png"`，说明**部分弹题是图题**（公式/图表以图片呈现）。
- **修复方向**：弹题题干解析要能抓取 `img` 的 `src`（注意可能用 `data-src` 懒加载），不要只取纯文本。不过因为答案已内嵌 DOM，图题对挂机而言也只是"读答案 + 关"而已。

### 【P2-2】选项随机排序（考试页确认；弹题需再验）

- **考试页实测**（`zhs-doexam.yaml`）：页面明确提示"选择题选项顺序为随机排列，请以选项内容为准"。这是**作业/考试（计分）场景**的特征。
- **弹题场景**：本次弹题选项顺序是 A/B/C/D 固定排列，且答案已内嵌，**顺序随机与否对挂机无意义**（反正直接读答案）。只有将来要"模拟点选正确项"时才需按内容匹配。
- **修复方向**：把"按内容匹配选项"逻辑只用在计分场景；课中弹题快路径不需要。

## 三、挂机自动化闭环设计（建议）

把"看课 + 弹题"和"作业/考试"拆成两条完全独立的链路：

```
┌─ 链路 A：挂机看课 + 课中弹题（主战场，本次重点）──────────────┐
│  轮询：video.paused? / dialog"弹题测验" 可见? / 验证码 iframe 阻塞? │
│  ① 弹题出现 → 读 DOM「正确答案：X」→ 记日志 → 点「关闭」        │
│  ② 关后 → video.play() 续播（轮询确认 paused=false）            │
│  ③ 验证码阻塞 → 暂停流程 → 提示人工过码 → 过完 play()          │
│  ④ 小节播完 → 自动切下一节（目录 listitem 点下一个）            │
└──────────────────────────────────────────────────────────────┘

┌─ 链路 B：作业 / 考试（附加内容，计分，答案不在 DOM）──────────┐
│  走原有 bank/solver/answerer，按内容匹配随机选项，人工兜底验证码 │
└──────────────────────────────────────────────────────────────┘
```

**节奏防御清单（降低 Turing 触发率）**：
- 弹题关闭加随机延迟 0.5~1.5s，不秒关
- 倍速 ≤ 1.5x，不长期拉满；必要时间歇恢复 1x
- 保持窗口可见（可缩小不可最小化），规避焦点检测
- 单节播完留 1~2s 再切下一节

## 五、补充发现（2026-10-19 实测续）

### 【P2-3】视频页实为 legacy 版本，不是文档假设的 wisdom 版

- **实测**：章节条目 DOM 是 `li.clearfix.video`，当前项 `.current_play`，完成图标 `.time_icofinish`。
  这三者在 `01-侦察报告.md` §2.5（legacy 版）里，而文档正文把本页当成 §2.2 的 wisdom 版（`.chapter-tree-74` / `.child-info.hasvideo`）。
- **影响**：插件站点识别 `VERSION_MAP` 里 `legacy` 分支的判断条件（`hostname.includes('studyvideoh5')`）能命中，但**章节条目 / 完成图标 / 当前项的选择器要按 legacy 版写**，不能用 wisdom 版的 `.child-info.hasvideo.current`。
- **修复方向**：本页统一走 legacy 分支选择器：`li.clearfix.video`（条目）、`.current_play`（当前）、`.time_icofinish`（已完成）。

### 【P1-3】已完结小节点击后直接停在结尾，挂机续播必须跳过已完结项

- **实测**：本课程共 53 小节，已完结 40 节。点击一个已完结小节（如 1.2），视频加载后 `currentTime === duration`（停在结尾），`ended=true`，`play()` 不前进。
- **影响**：若挂机循环"无脑点下一节再 play"，碰到已完结节会卡死（停在结尾不前进、进度不涨）。
- **修复方向**：点下一节前，先判该 `li.clearfix.video` 是否含 `.time_icofinish`；含则跳过，找下一个**未完结**节再点击。用"平台已记录完成"作为跳过判据，比"视频是否到结尾"更稳妥。

### 【P2-4】巩固弹题疑似仅"首次观看"触发

- **实测**：1.1（首次看）在 ~88% 处弹出 AI 助教小智弹题；1.2 已完结，用 `currentTime=448` 拖回中段重新播放到 ~469（已过 88% 点），**未再弹题**。
- **推测**：巩固弹题按小节首次观看下发，已完结小节重看不再弹。
- **影响**：对新开的课（每节都是首次看）每节都会弹，主路径覆盖充分；对已完结课重挂则无弹题、直接跳过即可。
- **修复方向**：弹题检测照常轮询即可（首次看必弹），不必为"重看不弹"特殊处理。

### 【P3-1】章节切换不能用 `li.click()`，会冒泡跳转到门户首页

- **实测**：在视频页对 `li.clearfix.video` 调 JS `.click()`，页面被带到 `https://www.zhihuishu.com/`（门户首页），丢失当前学习上下文；登录态在 profile 里保留，`goto` 回原 `studyvideoh5` URL 可恢复（未触发 SSO 掉登录）。
- **影响**：自动化脚本若用原生 `el.click()` 切章节，极易误触外层链接跳走。
- **修复方向**：
  - 切章节点**内部标题 generic**（含小节名的那个子节点），不要点 `li` 本身；
  - 或用 playwright 的 ref 点击内部可点元素；
  - 跳转后兜底：`location.hostname` 不是 `studyvideoh5` 时，`goto` 回 `stuStudy?recruitAndCourseId=...` 恢复。

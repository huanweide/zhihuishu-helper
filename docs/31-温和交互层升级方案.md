# 温和交互层升级方案（从「改属性」到「点按钮」）

> 提出：2026-11-15 ｜ 状态：**方案评审稿，未动代码**
> 原则一句话：脚本是辅助看课工具，不是破解器——所有播放控制优先「点页面自带的按钮，让页面自己的代码改状态」，深度操作只留兜底。
> 依据：docs/08-封禁风险与技术路径调研.md（行为风控是主战场）+ round-26 真机教训（isTrusted=false 合成事件被判脚本、seek 触发滑块）

## 〇、定位与术语对齐

- 脚本本体仍是油猴（Tampermonkey 注入 JS 这一步不可避免），**「不注入式」指的是操作页面的方式**：不劫持属性、不直改内部状态、不 hook API，而是像真人一样运用前端自身的交互——hover 出倍速菜单点 1.5x、点音量图标静音、点播放/暂停按钮、点「下一节」。
- **为什么温和 = 更低风险**（调研实据）：
  1. 页面自己改状态 → 无「外部属性突变」痕迹（MutationObserver 反向监控查不到）；
  2. UI 与内部状态天然一致 → 现在手动同步 `.speedBox span` 文本的做法是在补一个自造的检测点（03-player.js 作者自注：「避免平台检测播放器倍速与界面不一致」——温和化后这个检测点从根上消失）；
  3. 原生函数 hook 检测（`checkoutNotTrustScript` 校验 `XMLHttpRequest.open`/`attachShadow`）盯的是 hook，UI 点击不碰原生函数。

## 一、交互触点分级（全篇核心）

| 级别 | 名称 | 定义 | 风险 |
|---|---|---|---|
| **L1** | 原生 UI 点击 | 拟真点击页面自带控件（倍速菜单项/静音钮/播放暂停钮/下一节钮），页面自己的代码改状态 | 最低：零外部痕迹 |
| **L2** | UI 状态同步 | 裸改属性 + 手动同步 UI 文本（现 `setSpeed` 做法） | 中：属性突变 + 同步时序可查 |
| **L3** | 裸 API 兜底 | `v.play()` / `v.pause()` / `v.playbackRate=` 直调 | 仅在 L1 失败时使用，**每次调用必须打日志**（面板日志页可审计） |

**调用规则**：每个触点一律 L1 → 验收 →（失败）L3 回落，L2 只作为迁移期过渡保留、最终删除。验收 = 读 `video.playbackRate` / `muted` / `paused` 确认真变了，没变才算失败。

## 三、逐触点改造方案

### 3.1 D1 倍速 → `clickSpeedMenu(v, s)`（P1 阶段，最高优先）

```
L1: 拟真 mouseover → hover .speedBox（触发菜单展开）
    → 等 150~400ms 随机（菜单渲染 + 拟人反应时间）
    → 在展开的菜单列表里找文本匹配目标倍速的项（1.5 档平台原生就有）
    → realClickHuman 点它
验收: v.playbackRate === 目标值（播放器自己改的，UI 自动同步）
回落: 裸 v.playbackRate = s + 日志「倍速菜单未找到，降级直改」
```

- 收益：UI 同步代码删除，D1 检测点消失；`setSpeed` 保留为验收函数名不变，调用方（调度器）零改动。
- 边界：跨域 iframe 里点不到菜单 → 回落路径与现行为一致，能力不缩水。

### 3.2 D3+D4 播放恢复 → `clickPlayButton` 前置（P2 阶段）

- `ensurePlaying` 改序：先 `clickPlayButton(v)`（已有函数，UI 层）→ 验收 1.5s 内 `!v.paused` → 失败再裸 `v.play()` 兜底。
- `checkStall` 唤醒同改。
- 收益：裸 `play()` 从主路径降为兜底；「播放器内部状态拦截」问题 round-50 已验证 UI 点击反而更稳。

### 3.3 D2 静音 → `clickMuteButton(v)`（P3 阶段）

```
L1: realClickHuman 点 .volumeBox 的静音图标（或 [class*=mute] 按钮）
验收: v.muted === true || v.volume === 0（1.5s 内）
回落: v.volume = 0（保留——注释已证 muted 属性会被平台重置，volume 更稳；此为已知例外，日志说明）
```

- 注意：静音承担「绕过自动播放策略」职责，回落保底不能删，只降级为非常用路径。

### 3.4 D5 拟人暂停 → 点暂停按钮（P4 阶段）

- `maybeHumanPause` 触发时：L1 点播放器暂停钮（复用 clickPlayButton 的按钮清单取反向：`.prism-pause-btn`、`.vjs-pause-control` 等）→ 验收 `v.paused` → 回落裸 `pause()`。
- 到期恢复走 3.2 的播放路径（真人「回来了」点的是播放键）。

### 3.5 导航链序调整（P5 阶段，随代码评审定）

- 现链序 `spa → url → nativeNext → humanClick` 中 **spa 直调 Vue `$emit` / React `props.onClick` 属深度操作**（调内部方法）。
- 温和序调整：gotoNext 场景 `nativeNext`（点平台原生「下一节」按钮）提为首选；spa 降为 nativeNext/url 都失败后的兜底（任意跳转场景 nativeNext 语义不适用，spa 仍是必要的，保留但降级）。
- 风险提示：nativeNext 按钮存在性依赖页面版本，验收（`_waitSwitched`）已有，失败自动回落，无能力损失。

## 五、拟真事件序列规范（01-util 增强，随 P1 一并做）

- hover 展开：`mouseover`/`mouseenter` 先行 → 随机 150~400ms 停顿 → 点击；坐标在元素几何中心 ± 2px 随机偏移（现有坐标机制上加偏移）。
- 点击序列保持 mousedown→mouseup→click 三连（round-26 实证），间距加 10~50ms 随机。
- 一切新触点先探 `offsetParent !== null`（不可见不点，沿用 clickPlayButton 现约束）。

# 封禁风险与技术路径调研（四路证据交叉验证）

> 调研日期：2026-11-14 ｜ 方式：四路并行子代理独立检索（GitHub API 实抓 + 公开通报/文档/issue），结论带来源
> 起因：用户提出「避免封禁需要比油猴注入更深的技术路径」假设——本报告用证据检验该假设
> 边界：只调研公开资料；不做验证码破解、不做对抗式绕过指导；延续项目既有红线

---

## 〇、TL;DR（一分钟版）

1. **假设被证伪**：四路独立证据同向——「换协议流 / 换无痕自动化」都不降低封号风险。智慧树风控 2026 年已升级为**行为建模**（时长统计分布、上报节奏、答题速度），不看你用什么注入技术。
2. **协议流是被点名打击的对象**：fuckZHS PR #156（2026-05）实锤——平台针对「固定间隔上报（db_interval=30 等间隔请求）和匀速播放特征」风控升级，触发滑块 code:-12；PR #166 记录服务端时长回滚 code:-8。无行为熵的协议请求天然踩雷。
3. **无痕自动化不进「更隐蔽」赛道**：2025-2026 bot 检测生态（CDP Runtime.enable 泄露、TLS JA3/JA4、headless 特征、WebRTC 泄露）全部针对自动化浏览器设计。油猴寄生在用户日常 Chrome 里，TLS/硬件/IP/登录态就是用户本人，根本不进那个检测面。
4. **注入不是封号原因**：智慧树确有反注入（`checkoutNotTrustScript` 原生函数校验 + `window.OCS` 全局标记扫描），但产物只是前端警告。fuckZHS 弃 DOM 的真实原因是 hike 混淆+DevTools 检测阻碍逆向，不是被封。ocsjs 4317★ 大用户基数下封号公开报告率≈0。
5. **真正的风险分层**（官方通报证据）：视频侧异常 → 清进度/禁学（可恢复）；**做题侧异常 → 通报学校教务处 → 处分**。8 个真实处分案例全部涉第三方代刷/高倍速/挂机特征，未找到「仅自用、真实播放节奏、仍被处分」的实证。
6. **结论：主战场是行为拟人化，本项目既有红线（零 seek、倍速≤1.5、验证码交人、守株待兔）正是证据支持的正确方向**。演进选项见第六节。

| 发现 | 证据 |

### 1.2 无痕浏览器自动化（nodriver / camoufox / browser-use）

| 发现 | 证据 |
|---|---|
| CDP `Runtime.enable` 副作用 2024-06 被 DataDome 公开后广泛部署，约 5 行 JS 可检测，覆盖 console / ES6 Proxy 反制均被识破 | rebrowser.net；patchright deep-dive |

## 二、三路线暴露面对比

| 维度 | 油猴 DOM 流（本项目） | 协议逆向流 | 无痕自动化（Playwright/nodriver） |
|---|---|---|---|
| 环境指纹 | **用户本人**（TLS/IP/硬件/登录态全真） | 请求特征裸奔（无浏览器行为熵） | CDP 痕迹 + 新 profile 零历史 + WebRTC/时区一致性负担 |
| webdriver 标志 | false（天然） | — | true（除非 nodriver，仍有 CDP 泄露） |
| 被点名打击面 | 行为特征（倍速/时长/seek/答题速度） | **等间隔上报、匀速播放**（PR #156 实锤） | headless 判定、CDP Runtime.enable、TLS 指纹 |
| 维护成本 | 选择器失效有结构兜底 | 签名反混淆 + API 改版即断 | Chrome 升级连带修（单人维护项目尤甚） |
| 实证封号率 | ≈0（ocsjs 大基数） | ≈0 但有**时长回溯清零**案例（chaoxing #588） | — |
| 2026 生态趋势 | ocsjs 持续活跃 | 停更+社区补丁，无新项目 | 头部新项目 Autovisor 转入此路线 |

**交汇结论**：三条路线最终都处在同一套**行为风控**之下。换路线改变的是「逆向成本和功能上限」，不是封号概率。

## 三、演进选项（按证据强度排序，供决策，未动代码）

### 选项 1（证据最强，零代码）：维持既有红线 + 用户使用姿态引导
- 视频 ≤1.5 倍速、零 seek、验证码交人、守株待兔——全部与官方检测维度一一对应
- README / 使用说明补一段「低风险使用姿态」：规律时段学习（契合习惯分机制）、不跨设备并发、不代刷不传播（教育部等五部门 2022 文件追责对象是「组织代刷」）
- **做题侧是处分分界线**：`autoExam` 保持默认关，并在 README 把「做题侧异常 → 通报学校」的风险等级写得更醒目

### 选项 2（低成本低调化，1~2 小时工作量）
- 智慧树会扫 `window.OCS` 这类全局标记（scriptcat 实锤）；本项目挂 `window.ZHS` / `window.__ZHS_HELPER__` 同原理可被扫。可改为闭包内挂载或改用无特征命名，保留 console API 的同时降低被扫中面
- 该改动属「低调化」而非「对抗破解」，与项目「隐身性优先」红线一致

### 选项 3（行为熵增强，中等成本）
- 主循环抖动 ±0.5s 已有（对抗「完美 2s 周期」）；协议流被打击的「等间隔上报」本项目天然规避——视频心跳由播放器自身发出，脚本只保活不重构心跳，这是 DOM 流的结构性优势，保持不动
- 可补：挂机单次时长上限建议（如连续 3~4 小时后建议休息）、每日时段分布提示。均属面板提示层，不碰核心逻辑

### 选项 4（不推荐，记录原因）：迁移协议流或无痕自动化
- 证据不支持：协议流被点名打击 + 智慧树侧停更；无痕自动化新增 CDP/TLS/profile 三重暴露面
- fuckZHS 路线的真实收益只有「绕开 hike 混淆逆向成本」，与封号无关

## 四、局限声明

- 智慧树服务端风控细节无官方公开文档，所有机制结论来自脚本社区实测 + 高校通报反推
- proxyhat 等基准是公开测试页，作者自述不代表生产级反爬能力
- 「自用无实证处分」≠「自用零风险」：通报措辞不区分动机，异常判定即追责
- IP 跨度/多设备维度未找到智慧树侧公开证据（超星侧有「多设备登录封号警告」ocsjs #186）

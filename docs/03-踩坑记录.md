# 踩坑记录（ERRORS）

> 格式：现象 → 根因 → 解决 → 来源
> 本项目实测 + 参考项目逆向所得，按优先级排列。

## 【坑 1】倍速超过 1.8 平台不记录进度

**现象**：开到 2x / 3x，视频飞快放完，但平台学时进度停在原地甚至倒退。

**根因**：平台用 `timeupdate` 事件采样上报进度，倍速过高时采样点跳变太大，
后端校验不通过（判定为异常播放）。

**解决**：
```js
video.playbackRate = Math.min(config.speed, 1.8);
```

**来源**：Autovisor 源码 `configs.py` ——
```python
def limitSpeed(self) -> float:
    speed = self._safe_get_float('course-option', 'limitSpeed', 1.0)
    return min(max(speed, 0.5), 1.8)     # 硬夹在 0.5 ~ 1.8
```

## 【坑 2】最小化浏览器导致脚本卡死

**现象**：把浏览器最小化去干别的，回来发现视频停住、脚本无响应。

**根因**：浏览器对不可见标签页会**节流 `requestAnimationFrame` 和定时器**
（Chrome 最低降到 1 次/分钟），视频播放回调不再触发。

**解决**：
- 提示用户"可缩小不可最小化"
- 增加看门狗：检测 `currentTime` 长时间不推进 → 重新 `play()`

**来源**：用户提供的截图明确写了这条警告；ocsjs 的 notes 里也有。

## 【坑 3】视频放完但平台进度不满 100%

**现象**：视频播到结尾，`ended` 触发，但平台记录只有 80%，切下一节后学时没拿到。

**根因**：平台进度**异步上报**，且末尾几秒可能因网络抖动丢包。

**解决**：
```js
if (video.ended) {
  await sleep(3000);                       // 等上报
  const p = await getCatalogProgress();
  if (p >= 100) nextLesson();
  else {
    video.currentTime = (p / 100) * video.duration;   // 回退到记录点
    video.play();                                      // 重播
    // 最多重试 2 次，超过则跳过并告警
  }
}
```

**来源**：Autovisor `course_playback.py` 的 `retry_count >= 2` 逻辑。

## 【坑 4】浏览器自动播放策略拦截

**现象**：切课/刷新后，`video.play()` 返回 rejected，视频不自启。

**根因**：Chrome 的 Autoplay Policy ——
没有用户交互时，只有**静音**视频才允许自动播放。

**解决**：
```js
video.muted = true;                     // 必须置 true
video.play().catch(() => {});           // 吞掉 rejection
```

**来源**：greasyfork 558335 的实现要点。

## 【坑 5】`.controlsBar` 等控制条默认隐藏，点击无效

**现象**：`document.querySelector('.speedTab15').click()` 没反应，倍速改不动。

**根因**：播放器控制条默认 `display: none`（鼠标悬停才显示），
DOM 上虽然存在但**不可交互**。

**解决**：
```js
const controlsBar = document.querySelector('.controlsBar');
const speedList = document.querySelector('.speedList');
if (controlsBar && speedList) {
  controlsBar.style.display = 'block';
  speedList.style.display = 'block';
  document.querySelector('.speedList [rate="1.5"]')?.click();
}
```

**来源**：ocsjs `zhs.ts` 的 `switchSpeed` 方法。

## 【坑 6】倍速按钮 rate 属性 1.0 与 1 两种写法

**现象**：选择器 `.speedList [rate="1"]` 有时候选不中。

**根因**：新旧版本 HTML 里 1 倍速分别写成 `rate="1.0"` 和 `rate="1"`。

**解决**：
```js
const r = parseFloat(rate);
const sel = `.speedList [rate="${r === 1 ? '1.0' : rate}"], .speedList [rate="${r === 1 ? '1' : rate}"]`;
```

**来源**：ocsjs `zhs.ts` 注释 "兼容 1.0 和 1 的两个属性值兼容"。

## 【坑 7】开启了多个脚本，答案选不上 / 页面卡死

**现象**：装了其他刷课脚本后，选项点不亮，或页面无限刷新。

**根因**：多个脚本操作同一批 DOM，事件被抢/冲突。

**解决**：
- 启动时检测常见脚本的全局标记（如 `window.OCS`、`window.$zhs`），有则弹警告
- 提示用户只保留一个脚本

**来源**：用户截图警告 + greasyfork 脚本说明。

## 【坑 8】智慧树选项图片在 `data-src` 而非 `src`

**现象**：用 `img.src` 拿到的是占位图，OCR 识别出空白。

**根因**：智慧树做了懒加载，未进入视口的图片真实地址在 `data-src`。

**解决**：
```js
for (const img of question.querySelectorAll('.node_detail img')) {
  if (img.dataset.src) img.src = img.dataset.src;   // 提前触发加载
}
```

**来源**：ocsjs `zhs.ts` 中明确注释了这个特性。

## 【坑 9】SPA 路由切换不触发 load 事件，脚本不会重新初始化

**现象**：从课程列表点进播放页，脚本注入时页面还没渲染完，什么都找不到。

**根因**：智慧树是 SPA，路由变化不触发 `window.onload`。

**解决**：
```js
const observer = new MutationObserver(debounce(() => {
  if (document.querySelector('video') && !initialized) {
    initialized = true;
    init();
  }
}, 1000));
observer.observe(document.body, { childList: true, subtree: true });
```

**补充**：同时在初始化前 `await waitForElement('video', 20000)`，双保险。

**来源**：Autovisor `utils.py` 的 `page.wait_for_selector` 轮询模式。

**现象**：`#playTopic-dialog` 找到容器了，但里面查不到 `.topic-item`。

**根因**：部分版本的弹题内容渲染在 `#tmDialog_iframe` 里。


**来源**：wangzexi 脚本用了 `document.getElementById('tmDialog_iframe').contentWindow`。

## 【坑 11】滑块验证码（yidun）出现时脚本硬闯会被风控

**现象**：脚本继续操作，账号被判定异常。

**根因**：网易易盾验证码（`yidun_popup`）出现说明平台已经怀疑是机器人。

**解决**：
```js
if (isVisible('.yidun_popup, .yidun_modal, [id^="tcaptcha_transform"]')) {
  video.pause();                              // 停手
  panel.warn('检测到安全验证，请手动完成后脚本自动继续');
  await waitUntilHidden('.yidun_popup, .yidun_modal, [id^="tcaptcha_transform"]');
  panel.info('验证通过，继续运行');
}
```

**重要**：**不做自动过验证码**，风险太高，交给用户手动。

**来源**：Autovisor `tasks.py` 的 `wait_for_verify`（它也是提示手动）。

## 【坑 12】localStorage 在 iframe 里写，主页面读不到

**现象**：在播放器 iframe 里存了断点记录，刷新后主页面读出来是 null。

**根因**：iframe 与父页面**同源才能共享 localStorage**；
若跨域则是独立的存储空间。

**解决**：用 Tampermonkey 的 `GM_setValue` / `GM_getValue`，
它按**脚本 + 域**隔离但**跨 iframe/页面共享**。

```js
// 写
GM_setValue('resume:' + courseId, JSON.stringify({ lessonKey, time }));
// 读
const raw = GM_getValue('resume:' + courseId, null);
```

## 【坑 13】LLM 输出带解释导致答案解析失败

**现象**：模型返回 "答案是B，因为……"，直接拿去匹配选项失败。

**根因**：LLM 自发解释，即使 Prompt 说了"不要解释"。

**解决**：**答案归一化 + 正则提取**，不要直接信任原始输出。

```js
function normalize(raw) {
  const s = String(raw).trim().toUpperCase();
  const letters = s.match(/[A-D]/g);
  // 只有当去掉字母和分隔符后没有别的内容，才认为是纯选项答案
  if (letters && s.replace(/[\s,A-D、,，]/g, '') === '') {
    return [...new Set(letters)].sort().join(',');
  }
  if (/对|正确|TRUE|^T$/.test(s)) return '对';
  if (/错|错误|FALSE|^F$/.test(s)) return '错';
  return s;
}
```

**来源**：king-wang123 项目 + 实测经验。

## 【坑 14】LLM 单次输出不稳定

**现象**：同一道题问两次，答案不一样。

**根因**：`temperature = 0.7` 带来随机性。

**解决**：**多次生成投票取众数**（king-wang123 的做法是"直到出现重复答案"）。

```js
async function vote(title, options, type, n = 3) {
  const votes = {};
  for (let i = 0; i < n; i++) {
    const ans = normalize(await llm(title, options, type));
    votes[ans] = (votes[ans] || 0) + 1;
    if (votes[ans] >= 2) return ans;     // 提前收敛
  }
  return Object.entries(votes).sort((a, b) => b[1] - a[1])[0][0];
}
```

**来源**：king-wang123 `auto_answer_question.py` 的 `get_answer` 循环。

## 【坑 15】点击选项后未真正选中

**现象**：`option.click()` 调了，但提交时判定未作答。

**根因**：
- 页面用 `element-ui`，外层 `label` 点击事件被拦截
- 或多脚本冲突

**解决**：
```js
option.click();
await sleep(200);
if (!option.querySelector('input')?.checked) {
  // 退而求其次：点内层可见元素
  option.querySelector('.el-radio__inner, .el-checkbox__inner, label')?.click();
  await sleep(200);
}
```

**来源**：ocsjs 的 `work.handler` 里用 `.el-checkbox__input:not(.is-checked),.el-radio__input:not(.is-checked)`
精确选择**未选中**的元素，避免重复点击导致取消选中。

## 【坑 16】多选题重复点击会取消选中

**现象**：多选题点两次同一个选项，结果被取消了。

**根因**：`input.checked` 已经 `true` 时再 click 会 toggle 掉。

**解决**：**点击前先判断状态**：
```js
if (!option.querySelector('input')?.checked) {
  option.click();
}
```

**来源**：ocsjs 选择器里带 `:not(.is-checked)` 的原因。

## 【坑 18】重复 bindVideo 把进度记录"静默废掉"（本项目真 bug）

**现象**：脚本一切正常 —— 倍速生效、静音生效、视频在播，但
**GM 存储里永远没有续播记录**，关掉浏览器重开完全不续播。

**根因**：`Resume.bindVideo()` 里这段顺序错了 ——

```js
// ❌ 错误写法
bindVideo(video, courseId, lessonKey) {
  this._saveThrottled = U.throttle(() => { ... }, 5000);   // 先造新函数
  if (this._bound && this._boundVideo === video) return;   // 再守卫返回
  video.addEventListener('timeupdate', () => this._saveThrottled());
}
```

调用方 `07-main.js` 里 `bindVideo` 被调用**两次**（初始化一次、MutationObserver
补绑一次）。第二次调用虽然因守卫什么都没绑，**却把 `_saveThrottled`
覆盖成了一个没被任何事件触发的死函数** —— 于是已经挂上的 `timeupdate`
监听器回调里读到的 `this._saveThrottled` 是那个死函数，进度永远存不下来。

**为什么隐蔽**：不报错、不告警，日志里还打印了"已绑定进度记录到视频"，
表面完全正常。只有真的去看存储里有没有数据才抓得到。

**解决**：守卫前置 + 绑定序号 + 显式解绑。

```js
// ✅ 正确写法
bindVideo(video, courseId, lessonKey) {
  if (!video || !courseId) return false;
  if (this._boundVideo === video) return true;   // 守卫最前面，零副作用
  this._detach();                                 // 先解绑旧的
  const bindId = ++this._bindSeq;                 // 绑定序号
  this._boundVideo = video;
  const saveNow = () => { if (bindId !== this._bindId) return; ... };
  this._saveThrottled = U.throttle(saveNow, 5000);
  video.addEventListener('timeupdate', () => this._saveThrottled());
}
```

**怎么发现的**：puppeteer 截屏测试里断言 `window.__SHOT_STORE__['zhs-helper-resume']`
有值，结果死活是空 —— 顺着"存储键为空"这条线索挖出来的。

**警戒**：凡是「先做有副作用的初始化，再做幂等守卫返回」的写法都要警惕。
守卫必须**排在任何副作用之前**。

**回归防护**：`test/run.js` 第 19 组断言专门盯这个场景。

## 【坑 19】canvas.captureStream() 的 duration 是 Infinity

**现象**：测试用 `canvas.captureStream()` 造视频流，`video.duration` 是
`Infinity`，导致：
- `video.playbackRate = 1.5` **被 Chrome 静默忽略**（实测仍是 1）
- `percent()` / `atEnd()` 判定全部失真
- 续播 seek 行为不可测

**根因**：`captureStream()` 产出的是**直播流语义**，没有有限时长。
Chrome 对无界媒体流的 playbackRate 赋值会忽略。

**解决**：测试页面用 `Object.defineProperty` 打桩出有限时长
（`test/fixture-media.js`），并写一个定时器按 `playbackRate` 推进
`currentTime` + 派发 `timeupdate` —— 否则桩视频时间永远停在 0，
`Resume.save()` 的「前 5 秒不值得记」守卫会把所有写入拦掉。

注意 `duration` 的 `defineProperty` 必须给 **setter**（哪怕空实现），
否则脚本里 `v.duration = x` 这类兜底赋值会抛 TypeError。

**来源**：本项目实测 + MDN 关于 `HTMLMediaElement.playbackRate` 在无界流上的行为说明。

## 【坑 20】Shadow DOM 的 `shadowRoot.textContent` 包含 CSS 文本

**现象**：截屏测试断言面板里包含"运行中"，结果读到的是
`:host { all: initial; } .wrap { position: fixed; ...` —— 一大段 CSS。

**根因**：`shadowRoot` 里第一个子节点就是 `<style>`，
`shadowRoot.textContent` 会把 CSS 文本一并拼进来。

**解决**：断言**精确到字段**，不要读整段文本：
```js
h.shadowRoot.querySelector('.s-run').textContent   // → '运行中'
h.shadowRoot.querySelector('.s-ver').textContent   // → 'wisdom'
h.shadowRoot.querySelector('.s-cprog').textContent // → '1/5 (20%)'
```

**来源**：本项目截屏测试调试所得。

# 快照与回溯机制

> 目的：任何一次改动前都留一份可回滚的存档，改坏了随时退回去。

---

## 一、三层保护

| 层 | 工具 | 管什么 | 存哪 |
|----|------|--------|------|
| L1 | Git tag | 已入库的代码 | `.git/` |
| L2 | tar 快照 | 未入库的临时改动 + reference 参考源码 | `snapshot/*.tar.gz` |
| L3 | Git bundle | 整个仓库（防 `.git` 被误删） | `snapshot/*.bundle` |

---

## 二、日常用法

### 2.1 打快照（改动前）

```bash
bash tools/snapshot.sh "改动说明"
```

会生成：
- `snapshot/2026-09-17_2115_改动说明.tar.gz` —— 全量源码 + reference
- `snapshot/2026-09-17_2115_改动说明.bundle` —— 完整 git 仓库（含历史）
- 同时在 git 里打一个 tag `snap-2026-09-17_2115`

### 2.2 列快照

```bash
bash tools/snapshot.sh --list
```

### 2.3 回滚（恢复到某个快照）

**方式 A：只回滚源码（保留 git 历史）**
```bash
git checkout snap-2026-09-17_2115 -- .
```

**方式 B：整仓恢复（最彻底）**
```bash
cd ..
git clone zhihuishu-helper/snapshot/2026-09-17_2115_改动说明.bundle zhihuishu-helper-restored
```

**方式 C：只恢复某个文件**
```bash
tar -xzf snapshot/2026-09-17_2115_改动说明.tar.gz -C /tmp/restore
cp /tmp/restore/zhihuishu-helper/src/xxx.js ./src/
```

## 三、快照命名规范

```
YYYY-MM-DD_HHMM_<简短说明>.tar.gz
```

例：
- `2026-09-17_2115_M1骨架完成.tar.gz`
- `2026-09-17_2240_M2自动播放v0.1.tar.gz`

## 五、注意

- `snapshot/` 目录会占磁盘，单个快照约几 MB（含 reference）；定期清理旧的
- `.gitignore` 已排除 `snapshot/*.tar.gz` 和 `*.bundle`（不进 git，避免仓库膨胀）
- **reference/ 目录也是 git 忽略的**（第三方源码不入库），
  但**会打进 tar 快照**，所以参考源码也可回溯

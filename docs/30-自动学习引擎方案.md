## 一、智慧树平台机制（实测结论）

### 1.1 站点与页面族

| 页面 | URL 特征 | 用途 |
|------|----------|------|
| 课程学习页（主目标） | `studyvideoh5.zhihuishu.com/stuStudy?recruitAndCourseId=...` | legacy 旧版共享课，视频 + 目录 + 弹题 |
| 课程中心 | `hike-teaching-center.polymas.com/stu-hike/agent-course-hike/ai-course-center` | 选课列表（虚拟滚动卡片） |
| 课程学习页（hike） | `.../AIstudent/{courseId}/{classId}?key=entry` | hike 体系学习页 |
| 作业/考试作答页 | `#/webExamList/dohomework/{...}` / `doexamination/{...}` | 守株待兔答题 |
| 作业/考试列表页 | `#/webExamList`（不含上面两者） | 只读，脚本绝不自动点 |

页面适配由 `02-adapter.js` 的 6 套适配器「评分选举」选出当前站点的目录结构，
选不出来走 `auto` 通用降级 + `sniffItems` 兜底。

### 1.2 课程播放闭环（当前实现）

```
进入课程页
  → 07-main.bootOnce：挂面板 → 识别目录 → 取 courseId → 等 video
  → 04-Resume.restore：有记录就「点标题切到该节，位置交给平台」（零 seek）
  → 无记录且当前节已学完 → 跳到首节未学（skipFinished 开启时）
  → 绑定 video 进度记录 → 05-Scheduler 主循环（2s/tick）开跑
```

主循环每 tick 做：守卫0 页面被带走→回家 ｜ 守卫1 验证码→停手等人 ｜
守卫2 弹题→即时处理 ｜ 保活（卡死检测/进度对账/拟人随机暂停/ensurePlaying）｜
结束判定 → `gotoNext` 切下一节。

### 1.3 弹题 / 作业 / 考试答题闭环

```
课中弹题（守卫2 → 13-Answerer.handleDialog）
  → 采集题干+选项（08-Questions.Dialog）
  → AI 随堂练习分流（.ai-test-question-wrapper / .ai-class-exercise-dialog）
  → 标准链路：Solver.solve → Filler 回填 → isChecked 自检 → 关弹窗 → 恢复播放
  → 非标准 A/B：先真求解，求不出才按 gatedRandom 决定是否猜
求解链（11-Solver.solve）：
  精确缓存 → 模糊缓存(90%) → 题库(09) → LLM 投票(10) → 启发式(11b) → 跳过/随机
作业/考试（06c-Exam，守株待兔）：
  用户自己点进作答页才工作；autoExam 严格门禁；章节范围过滤；答完即停，绝不跳转
```

### 1.4 切课 / 跳课闭环

```
本节课学完（05.onLessonEnd 判定：平台记录金标准 / 进度≥91% / 0% 等 3min 交人）
  → gotoNext：随机延迟 2~8s → Nav 策略链（spa→url→nativeNext→humanClick）
    → 四信号验收 → 穷举兜底 → 成功后 rebind + 恢复播放
本课全看完（bd.undone===0 且 trulyAllDone）
  → autoCourseHop 开启：markCourseDone → returnToHub（写 via='auto-hop' intent）
  → 课程中心 onPageReady：认领 auto-hop 意图 → pickNext 选未看完课 → enterCourse
  → 学习页 settleIntentOnStudentPage 回写确认
```

### 1.5 八条硬约束（改上述任何逻辑前必读，`docs/05` 为宪法）

1. **绝不 seek**：`video.currentTime = x` 触发腾讯 Turing 滑块，进度作废。断点交给平台。
2. **倍速 ≤ 1.5**：更高不记录进度。
3. **不能最小化浏览器**：rAF 停摆 → 卡死。
4. **验证码交人**：检测到激活态 → 停手等人，绝不自动破解、绝不超时放行。
5. **切集只点标题**，切后关温馨提示（只点「我知道了」/X，不碰「返回学堂」）。
6. **跳过已完成 + 每次重扫**（不缓存清单）。
7. **拟人节奏**：弹窗关闭 0.5~1.5s 随机、拟人随机暂停 0.3%/tick、切课延迟 2~8s。
8. **作业/考试守株待兔**：绝不自动跳转到作业/考试页、绝不自动点列表页。

## 二、三个新功能设计

### 2.1 autoLearn —— 自动学习总开关（默认开启）

**需求**：打开课程中心即自动进入「进度未达 100%」的课程开始听；当前课听完自动退出、
寻找下一门未看完的课；断点续播；支持手动选节。

**与旧设计的差异**：原 `onPageReady` 只有在 `intent.via === 'auto-hop'`
（即「上一门课由本脚本学完后自动跳回」）时才自动选课；用户手动打开课程中心不自动点
（防劫持）。新增 `autoLearn`（默认 true）后：

- `autoLearn` 开 → 打开课程中心即视为「已授权自动学习」，直接 `runOnHub('auto-learn')`；
  首次自动选课打 info 日志 + 面板提示，让用户看得见（不静默劫持）。
- `autoLearn` 关 → 完全维持旧行为（只认 auto-hop 链），向后兼容。

**红线核对**：autoLearn 只作用于「听课链」（课程中心 → 学习页）。
作业/考试页的守株待兔红线（第 8 条）**不受影响**——本功能不碰 `#/webExamList`。

**配置落点**（`00-config.js`）：
- `DEFAULTS.autoLearn = true`
- 加入 `BOOL_KEYS`（布尔归一化）
- `CONFIG_REV` 5→6，`FORCE_UPGRADE.autoLearn = true`（老用户强制拿到默认开启）

### 2.2 gotoLesson —— 手动选择指定课时

**需求**：「确认自己可通过其他方式选择某一节课程」。

**设计**：新增 `ZHS.Scheduler.gotoLesson(target, opts)` + 运行时 API `zhs.gotoLesson(target)`。
- `target` 为数字 → 目录第 N 节（1 起）；为字符串 → 按标题子串匹配。
- 复用 `Nav.jumpTo` + `_exhaustiveSwitch` + `_rebindAfterNav` 全套稳健切换，
  成功后更新 `lessonKey`、 rebind 续播、重置答题签名；失败回滚 `lessonKey`。
- 面板新增「跳到指定课时」输入框 + 按钮 + 「找下一门课」按钮（调 `CourseHub.triggerManual`）。

**为什么复用而非新写**：切课的「点击→验收→穷举兜底→rebind」是 round-14~39c 反复踩坑
固化下来的，任何简化都会重新引入「点了没反应/记错节」的老 bug。gotoLesson 只换「目标怎么来」，
切换执行体完全复用。

### 2.3 LLM 置信闸门 —— 提高正确率 + 永不瞎选

**需求**：「对于考试测验界面的 LLM 选择提高正确性，永远不瞎选」。

**现状**：`10-llm.vote` 多次生成取众数，但**不看票型**——1:1:1 三票分裂也照样返回
第一个最高票，等于把「没把握」当成「有答案」。`11-solver` 拿到 LLM 答案即采用。

**设计（三层，全部不破坏 644 测试）**：

1. **Prompt 升级（最大正确率杠杆）**：`buildPrompt` 重写为
   「逐步推理 + 排除法 + few-shot + 严格单Token输出」。
   关键：引导模型「先逐个分析选项对错、排除明显错误项，再给最终答案」，
   但**最终仍只输出答案字母**（保 Bank.normalize 可解析）。模型被要求思考时正确率显著更高，
   这是纯增益、无输出格式风险。
2. **投票置信追踪**：`vote()` 仍返回答案字符串（保持测试桩 `vote = () => 'B'` 可用），
   但把票型写进 `LLM.getLastVoteMeta()`：`{confidence: high|medium|low, distribution, unanimous, n}`。
   - 全票一致 → high；过半多数 → medium；分裂无多数 → low。
3. **低置信处理（永不把没把握当答案）**：
   - 选择题温度 0.3→0.1（提稳定性，减少无谓分裂）。
   - `vote` 检测到「无多数」且预算还有余量时，用「排除法」prompt 补投一次破平局。
   - `11-solver` 读 `lastVoteMeta`：LLM 低置信时与离线启发式**交叉验证**——
     两者一致 → 提升为 medium 并采用；仅记录置信度供报告标注「请提交前检查」。
   - **不引入新的随机兜底**：`gatedRandom` 仍默认关，「永不瞎选」的承诺不变。
